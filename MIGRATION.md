# Supabase → Firebase migration

Backend now runs on Firebase (Auth + Firestore, free Spark plan) with Cloudinary for image
hosting (Firebase Storage requires the paid Blaze plan even at zero usage, so we skip it).

> Rotate your Supabase service role key if you haven't — it was exposed in the uploaded `.env`.

## 1. Create the Firebase project

1. [console.firebase.google.com](https://console.firebase.google.com) → Add project (Spark/free plan).
2. Build → Authentication → Get started. Enable **Email/Password** and **Google** sign-in providers.
3. Build → Firestore Database → Create database (production mode, pick a region).
4. Project settings → General → Your apps → Add app → Web. Copy the config values.

## 2. Configure the app

Fill in `.env`:

```
FIREBASE_API_KEY=...
FIREBASE_AUTH_DOMAIN=your-project.firebaseapp.com
FIREBASE_PROJECT_ID=your-project
FIREBASE_MESSAGING_SENDER_ID=...
FIREBASE_APP_ID=...
CLOUDINARY_CLOUD_NAME=...
CLOUDINARY_UPLOAD_PRESET=...
```

```bash
npm install
npm run dev
```

## 3. Set up Cloudinary (image hosting)

1. Sign up free at [cloudinary.com](https://cloudinary.com) — no card required.
2. Copy your **Cloud name** from the dashboard into `CLOUDINARY_CLOUD_NAME`.
3. Settings → Upload → Add upload preset. Set **Signing Mode: Unsigned**, give it a name,
   save. Put that name in `CLOUDINARY_UPLOAD_PRESET`.

## 4. Deploy Firestore rules and indexes

```bash
npm install -g firebase-tools
firebase login
firebase use --add
firebase deploy --only firestore:rules,firestore:indexes
```

Without this, all reads/writes are blocked by Firestore's default rules.

## 5. Seed data

- Bring over existing Supabase data: see `scripts/migrate-from-supabase.mjs`.
- Or start fresh — add categories, delivery options, and products from the admin panel.

## 6. Create your first admin account

1. Register an account at `/auth/register` (email/password or Google).
2. In Firebase Console → Firestore Database → `users` collection, find your uid's document,
   change `role` from `customer` to `admin`.
3. Reload the site — you'll see the Admin Dashboard link.

## 7. Google Sign-In and authorized domains

`localhost` is authorized by default. Once deployed elsewhere, add that domain under
Authentication → Settings → Authorized domains, or Google Sign-In fails there.

## What changed

- **Auth**: Supabase Auth → Firebase Auth (email/password + Google). Signup creates a
  `users/{uid}` Firestore profile doc, since Firebase has no auth-trigger equivalent.
- **Database**: Postgres tables → Firestore collections. No joins, so a product embeds its
  category and variants, and an order embeds its line items.
- **Order numbers**: generated by an atomic counter doc (`counters/orders`) instead of a
  Postgres sequence.
- **Images**: uploaded to Cloudinary (compressed client-side first) instead of pasted URLs.
- **Access control**: Supabase RLS → `firestore.rules`, checking `users/{uid}.role == 'admin'`.

## Note on "doesn't sleep"

Firestore and Auth are always-on managed services, same as Supabase's own DB/auth were. This
app has no server API routes, so there's nothing here that can cold-start.
